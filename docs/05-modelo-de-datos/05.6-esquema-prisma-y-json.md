## 2. Especificación Interna del Campo `Contract.schemaJson`
Tanto el formulario guiado (Etapa 1A) como el asistente de contratos con IA (Etapa 1B) producen exactamente esta estructura validada con **Zod**. El archivo `.ts` final (`tsContent`) se genera determinísticamente en el servidor a partir de este JSON y se muestra al usuario en **solo lectura**.

```json
{
  "description": "Autentica a un usuario registrado y entrega su sesión",
  "authRequired": false,
  "allowedRoles": [],
  "request": {
    "pathParams": [],
    "queryParams": [],
    "body": [
      { "name": "correo", "type": "string", "required": true, "description": "Correo electrónico del usuario" },
```

### Alcance de Tipos y Validaciones Anti-Inyección (MVP)
1. **Tipos permitidos (únicos soportados en V1):** `"string"`, `"number"`, `"boolean"`, `"string[]"`, `"number[]"`, `"iso-date"`.
   * *Límites explícitos:* No se admiten objetos anidados, valores `null` ni uniones personalizadas en el generador del MVP; cualquier solicitud con esas estructuras debe rechazarse con mensaje claro.
   * *Campos opcionales:* Cuando `required: false`, el generador emite propiedad opcional en TypeScript (`campo?: tipo`).
2. **Validación estricta contra inyección de código TypeScript (Zod):**
   * `name` de cada parámetro/campo: debe cumplir `^[a-zA-Z_][a-zA-Z0-9_]*$` (máx. 64 caracteres) y no pertenecer a la lista de palabras reservadas de JavaScript/TypeScript.
   * `code` de cada error: debe cumplir `^[A-Z][A-Z0-9_]{1,48}$`.
   * `description` y `message`: se sanean antes de insertar en comentarios JSDoc o literales TS (eliminando secuencias `*/`, caracteres de control y normalizando saltos de línea).
